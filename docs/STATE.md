# Bébé Bonjour — state of play (2026-11-20)

Repos: `bebebonjour-app` (this one: Convex backend + workers), `bebebonjour-landing` (Vite site), `bebebonjour-ops` (private Next.js console).

## 1. Goal

A parent asks for a French or Arabic digital birth announcement (optional narration in a father or mother voice, VoxCPM2). An operator reads the request and launches generation from a short brief; public orders pay €39 first. The announcement is published at a private link and emailed, then corrected and approved by the parent.

## 2. What works today

- **Landing** https://www.bebebonjour.com (19/11) — sells the €39 announcement around a real example: the hero plays the Amal announcement in one click (Codex text + Cedar voice from the 5 Oct production run) and links its static, non-indexed copy https://www.bebebonjour.com/exemple/amal/. It states the price, what you receive (page, text, voice, 2 corrections, 12 months online) and the flow *describe → we read your request → you pay → your announcement arrives*. `/delivery` now follows that flow (19/11). The `/demo` pages stay online, unlinked.
- **Direction A (19/11)**: landing promise "Son prénom, révélé à la fin."; `/delivery` uses the same tokens and fonts (served by the landing at `/fonts/`, `font-src 'self'`) and asks message → meaning of the name → language/gender/date → first name → email. The optional meaning is appended to `request` as `Sens du prénom : …`.
- **R1 slideshow render (19/11, `b2a7c40`)**: `renderAnnouncement` draws one screen per phrase from `buildAnnouncementChapters`, bars per chapter, name reveal then forest state; screens follow `phraseStarts` when narration provides them, otherwise tap/arrows (`docs/r1-announcement.md` § Render). Convex prod has the matching announcement CSP (script hash, `sandbox allow-scripts`). Per-phrase narration (19/11): the worker speaks each screen and publishes its `phraseStarts`.
- **R1 live in prod (19/11, t_85eb28f2)**: Convex `tacit-antelope-577` and the `bebebonjour-delivery-loop` worker run the same main commit (see Git map). New announcements are R1: chapters, name revealed last, screens switched on the voice. Fixed on the way: the Convex CSP hash did not match the page script (Convex minifies `Function.toString`), so the slideshow script was blocked; the audio route now serves byte ranges so tapping a screen seeks the voice. **Rollback**: drop-in backup `~/.local/share/bebebonjour-delivery-loop-runtime/20-approved-runtime.conf.ea028cb.bak` (worker `ea028cb`) + `npx convex deploy` from `60e4b22` (Convex before this ship). - **Voices on the gamer tower (19/11, t_70ea6d28)**: narration uses the VoxCPM2 voices "Père, chaleureux" and "Mère, douce" (fr + ar), generated by the `voice-worker` container on the tower's RTX 5070 Ti (Arcane, Gamer Tower env, project `bebebonjour-voice`; LAN only: `http://192.168.1.211:38131`, Windows firewall allows the VM alone). The VM worker calls it directly and wakes the tower by Wake-on-LAN. Before claiming a narrated job it asks `/ready` (ready when GPU use ≤ 30 % over a short window and ≥ 6 GB VRAM free, so game pauses are used too); otherwise the job stays queued, oldest first, no attempt consumed, and the ops console shows "En attente de la voix". The model loads on demand (~16 s) and frees VRAM after 5 min idle; one announcement takes ~35 s of GPU for fr + ar and peaks at ~5.7 GB VRAM. Tower image: `bebebonjour/voice-worker:3358578`. No paid voice server; moving to one later is a URL change (`BEBEBONJOUR_VOICE_WORKER_URL`).
- **Production backend on Railway (19/11, t_85a907e4)**: orders, payments, generation, publication and mail run on Railway project `bebebonjour-production` (`api` = this repo `d4573de`, https://api-production-c9013a1c.up.railway.app, + `Postgres`). The landing rewrites, the ops console (`BEBEBONJOUR_BACKEND_URL`) and the worker (`CONVEX_URL` in `runtime.env`) point there; the Stripe live webhook URL is unchanged and follows the rewrite. Convex `tacit-antelope-577` is **paused, not deleted**, holding exactly the copied data. Switch record and rollback: `docs/railway-migration.md` §4–5.
- **Name meaning in the brief (19/11, t_b52074c0)**: the brief has an optional `nameMeaning` (ops console field "Sens du prénom ou raison du choix", prefilled from the customer's "Sens du prénom"). - **Order path (20/11, t_d4384d69)**: "Créer mon faire-part" → `/delivery` (proxied by the landing's Vercel rewrites to the Railway `api`) → paid form only, "Envoyer ma demande" (no card asked at submit, no password field). Invited families use `https://www.bebebonjour.com/delivery?mode=offert#code=<password>`: the browser prefills the offer password from the fragment (never sent to the server); that free request also waits for the operator. When the paid route is off, `/delivery` says orders are closed. The order page states: reading the request, pay 39 €, payment being confirmed, payment not completed (nothing charged, retry), link expired (open a new payment), payment received/creation in progress, correction being read, new version in progress; support `contact@bebebonjour.com`. **Live in prod 20/11** (api `c8d6285`): a public request without code went submit → operator launch → "Payer 39 € par carte" → live Stripe Checkout (`cs_live_…`, 39,00 €), not paid; `BEBEBONJOUR_PAID_TERMS_URL` now points at `https://www.bebebonjour.com/delivery/terms/route-a-39-v2` (the old Convex URL answered 500).
- **Operator gate (live in prod since 19/11, app `22fb776`, ops `513dd1a`)**: requests wait in `awaiting_operator`; the owner gets an email at `BEBEBONJOUR_OPERATOR_EMAIL` with a link to `/commandes/<jobId>` in the ops console (`BEBEBONJOUR_OPS_CONSOLE_URL=https://bebebonjour-ops.vercel.app`), edits the brief (first name, Arabic name, gender, date, faith context, tone, up to 3 phrases) and launches or refuses. Paid: launch → customer email with the payment link → Stripe settlement → generation. Codex receives only the brief. Spec: `docs/operator-gated-intake.md`. Checked in prod 19/11: a real request waited, the owner email and the payment-link email were sent, the live €39 Checkout opened, and no generation was claimed while payment was pending.
- **Paid €39 route**: `BEBEBONJOUR_PAID_ROUTE_A_ENABLED=true` again since 19/11 (was off 18/11 until the operator gate shipped). Terms `route-a-39-v2`. Live webhook `we_1UdEfEGrir6mz3o7Gwbqmkqm` → `https://www.bebebonjour.com/delivery/payment/webhook` (`payment_intent.succeeded`). No real card payment yet.
- `bebebonjour-ops` main: private operations console; `/commandes` lists delivery-loop orders and `/commandes/<jobId>` launches or refuses (`BEBEBONJOUR_OPS_ENABLED_ACTIONS` includes `launch_generation,refuse_request`).
