# Bébé Bonjour — state of play (2026-11-19)

Repos: `bebebonjour-app` (this one: Convex backend + workers), `bebebonjour-landing` (Vite site), `bebebonjour-ops` (private Next.js console).

## 1. Goal

A parent asks for a French or Arabic digital birth announcement (optional Cedar narration). An operator reads the request and launches generation from a short brief; public orders pay €39 first. The announcement is published at a private link and emailed, then corrected and approved by the parent.

## 2. What works today

- **Landing** https://www.bebebonjour.com (19/11) — sells the €39 announcement around a real example: the hero plays the Amal announcement in one click (Codex text + Cedar voice from the 5 Oct production run) and links its static, non-indexed copy https://www.bebebonjour.com/exemple/amal/. It states the price, what you receive (page, text, voice, 2 corrections, 12 months online) and the flow *describe → we read your request → you pay → your announcement arrives*. `/delivery` now follows that flow (19/11). The `/demo` pages stay online, unlinked.
- **Direction A (19/11)**: landing promise "Son prénom, révélé à la fin."; `/delivery` uses the same tokens and fonts (served by the landing at `/fonts/`, `font-src 'self'`) and asks message → meaning of the name → language/gender/date → first name → email. The optional meaning is appended to `request` as `Sens du prénom : …`.
- **R1 slideshow render (19/11, `b2a7c40`)**: `renderAnnouncement` draws one screen per phrase from `buildAnnouncementChapters`, bars per chapter, name reveal then forest state; screens follow `phraseStarts` when narration provides them, otherwise tap/arrows (`docs/r1-announcement.md` § Render). Convex prod has the matching announcement CSP (script hash, `sandbox allow-scripts`). Per-phrase narration (19/11): the worker speaks each screen and publishes its `phraseStarts`.
- **R1 live in prod (19/11, t_85eb28f2)**: Convex `tacit-antelope-577` and the `bebebonjour-delivery-loop` worker run the same main commit (see Git map). New announcements are R1: chapters, name revealed last, screens switched on the voice. A fictional request (free path, owner inbox) went submit → operator launch → Codex → Cedar → publish → draft email in 30 s. Fixed on the way: the Convex CSP hash did not match the page script (Convex minifies `Function.toString`), so the slideshow script was blocked; the audio route now serves byte ranges so tapping a screen seeks the voice. **Rollback**: drop-in backup `~/.local/share/bebebonjour-delivery-loop-runtime/20-approved-runtime.conf.ea028cb.bak` (worker `ea028cb`) + `npx convex deploy` from `60e4b22` (Convex before this ship). Roll both back together: the old worker fails publication against the new Convex.
- **Production backend on Railway (19/11, t_85a907e4)**: orders, payments, generation, publication and mail run on Railway project `bebebonjour-production` (`api` = this repo `d4573de`, https://api-production-c9013a1c.up.railway.app, + `Postgres`). The landing rewrites, the ops console (`BEBEBONJOUR_BACKEND_URL`) and the worker (`CONVEX_URL` in `runtime.env`) point there; the Stripe live webhook URL is unchanged and follows the rewrite. Convex `tacit-antelope-577` is **paused, not deleted**, holding exactly the copied data. Switch record and rollback: `docs/railway-migration.md` §4–5.
- **Name meaning in the brief (19/11, t_b52074c0)**: the brief has an optional `nameMeaning` (ops console field "Sens du prénom ou raison du choix", prefilled from the customer's "Sens du prénom"). Since t_872efb61 the `meaning` chapter uses `nameMeaning` first, else the verified catalog meaning, else the parents' reasons from the phrases; the console shows the catalog meaning under the field.
- **Name catalog (19/11, t_9a36af38)**: `data/reference-catalog.json` holds 167 sourced names (INSEE 2025 top names + common Arabic names, all ranked in INSEE 2025), 24 with Quranic verses checked against `data/quran-verses.json`. A recognised name gives Codex its meaning when the operator leaves `nameMeaning` empty. Sources and how to add a name: `docs/name-catalog.md`. Live check: fictional Youssef (islam, ar+fr) published with its meaning and Yusuf 12:4 in both languages.
- **Order path (19/11)**: "Créer mon faire-part" → `/delivery` (proxied by the landing's Vercel rewrites to the Railway `api`) → paid form "Envoyer ma demande" (no card asked at submit). A hidden "J’ai un mot de passe offert" form keeps the free offer; it also waits for the operator.
- **Operator gate (live in prod since 19/11, app `22fb776`, ops `513dd1a`)**: requests wait in `awaiting_operator`; the owner gets an email at `BEBEBONJOUR_OPERATOR_EMAIL` with a link to `/commandes/<jobId>` in the ops console (`BEBEBONJOUR_OPS_CONSOLE_URL=https://bebebonjour-ops.vercel.app`), edits the brief (first name, Arabic name, gender, date, faith context, tone, up to 3 phrases) and launches or refuses. Paid: launch → customer email with the payment link → Stripe settlement → generation. Codex receives only the brief. Spec: `docs/operator-gated-intake.md`. Checked in prod 19/11: a real request waited, the owner email and the payment-link email were sent, the live €39 Checkout opened, and no generation was claimed while payment was pending.
- **Paid €39 route**: `BEBEBONJOUR_PAID_ROUTE_A_ENABLED=true` again since 19/11 (was off 18/11 until the operator gate shipped). Terms `route-a-39-v2`. Live webhook `we_1UdEfEGrir6mz3o7Gwbqmkqm` → `https://www.bebebonjour.com/delivery/payment/webhook` (`payment_intent.succeeded`). No real card payment yet.
- `bebebonjour-ops` main: private operations console; `/commandes` lists delivery-loop orders and `/commandes/<jobId>` launches or refuses (`BEBEBONJOUR_OPS_ENABLED_ACTIONS` includes `launch_generation,refuse_request`).
